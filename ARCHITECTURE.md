# Architecture

How kovadapt is put together, and the contracts that fail SILENTLY when broken.
Read this before changing anything under `kovadapt/` — most of what follows was
learned by shipping the bug first.

## What this is

kovadapt adapts KovaaK's aim-training scenarios **between** runs (the game has no modding API). It watches the game's stats folder; after each run it updates a per-scenario player model and rewrites `<Scenario> [Adaptive].sce` so the next load targets the player's weaknesses. Windows is the runtime target (Raw Input telemetry, dxcam clips, the game itself); analysis and the test suite run on any OS.

## Commands

```
pip install -e .[dev]                 # core (numpy only) + pytest + ruff
pip install -e .[gui]                 # + PySide6/pyqtgraph/psutil desktop app
pytest                                # full suite, cross-platform, ~4 min
pytest tests/test_adapt.py -k bandit  # single file / keyword
ruff check .                          # lint (line-length 100, target py310)
```

CLI (console script `kovadapt` or `python -m kovadapt`): `gui | scenarios [filter] | play "<scenario>" | watch "<scenario>" | generate "<scenario>" | status "<scenario>" | replay "<scenario>" | checkup | watchdog`. Scenario-taking commands strip a trailing `[Adaptive]` from the argument (compounding guard). Standalone exe: `powershell -File packaging/build.ps1` (PyInstaller one-dir; `packaging/entry.py` routes GUI/CLI/`--watchdog` through one binary).

- `tests/conftest.py` inserts the repo root into `sys.path`, so pytest works without installing the package.
- Integration tests `pytest.skip` unless a real KovaaK's install exists (`KOVAAKS_ROOT` env var, else the default Steam path) — a green run does not prove real-file parsing was exercised.

## Architecture

### The adaptation loop (`kovadapt/watcher.py`)

`SessionWatcher.watch()` polls `<kovaaks_root>/stats/` (1 s poll, 1.5 s write-settle so KovaaK's finishes writing) and for each new CSV of the base **or** adaptive scenario runs `process_run()`:

1. `stats/parser.py` parses the CSV into a `Run` (per-kill `KillEvent`s + summary dict).
2. `analysis/report.py:build_report()` joins the run with a slice of the live mouse recording (`run_time_window()` reconstructs the run's epoch window from CSV wall-clock kill timestamps), producing a `RunReport`: flick segmentation, directional bias, per-region deficits, notable moments, input-health metrics (`MouseTrace.input_health()`). The watcher's session-scoped `SessionFatigueTracker` (`analysis/fatigue.py`, Theil-Sen trend, reset every `watch()`) stamps `rep.fatigue`. Persisted as JSON; clips extracted from the dxcam ring buffer must happen immediately or the buffer rolls past.
3. `adapt/engine.py:AdaptationEngine.observe()` folds the run into the `PlayerProfile` — bandit credit **first** (reward is measured against the pre-run accuracy EWMA), then EWMAs, then the directional-bias EWMA. When telemetry region deficits exist they *replace* run-level focus attribution. First run also stamps `profile.archetype` (`adapt/archetype.py`: name keywords, then shots-per-kill heuristic, default "clicking") — every engine call resolves settings through `Settings.for_archetype()`.
4. `AdaptationEngine.plan()` runs the controllers — deadband size controller (hold hit rate in the archetype's band), Thompson-sampling bandit over the wall-region grid, Ornstein-Uhlenbeck movement drift with pace coupling, dodge-direction skew from `profile.ewma_bias` — and returns an `AdaptationPlan`. The optional `fatigue` argument eases only the **emitted** plan (bigger/calmer targets); persisted profile state stays un-eased.
5. `scenario/generator.py:generate_adaptive_variant()` applies the plan to the **base** `.sce` (never the previous variant — multipliers are absolute, edits never compound) and writes `<Base> [Adaptive].sce`.
6. The profile is saved (atomic tmp+replace), and only THEN is `on_report` fired — GUI handlers reload the profile from disk, so an earlier emit would show last run's state. History predating `watch()` is ignored; the `replay` command is the only way to backfill it (it merges base+adaptive runs chronologically).

The live recording keeps a rolling window (`Settings.telemetry_retention_min`, default 30 min; 0 = unbounded) — runs are sliced out within seconds of ending, so only the recent window is ever needed. Zero-kill runs (no reconstructable time window) are analyzed without telemetry rather than slicing the whole session.

The GUI (`kovadapt gui`) wraps this loop in a single QThread (`gui/workers.py:WatcherWorker`); watcher callbacks fire on the watcher thread and are bridged into Qt as signals — never touch widgets from them. Stopping is cooperative (`request_stop()` flag, ~1 s latency); `watch()` must never reset `stop_requested` (a stop request landing during startup has to win).

### Packages

- `config.py` — `Settings` dataclass holding every tunable; KovaaK's path discovery (`KOVAAKS_ROOT` env var wins); `ADAPTIVE_SUFFIX`. `Settings.save()` and `load()` both default to the canonical `~/.kovadapt/settings.json` regardless of a customized `profile_dir` (bootstrap location must be knowable).
- `launcher.py` — stdlib-only launch integration: install/ownership check (Steam library appmanifest; walks parents for `steamapps`, resolving junctions), `steam://run/824270` game launch, deep-link URL builder, and playlist writing in the game's own JSON schema (`scenario_name`/`play_Count` casing is load-bearing; UTF-8 no BOM, CRLF). **Deep links cannot open locally-generated scenarios (manually verified)** — the Play flow is playlist-first; the deep link is best-effort.
- `stats/` — CSV → `Run`/`KillEvent`. Positional kill-row columns and summary keys **with trailing colon** (`"Score:"`, `"Hit Count:"`) are the contract with KovaaK's 3.9.x output.
- `profile/` — `PlayerProfile`: EWMA stats, per-region Gaussian `RegionPosterior`s (mean > 0 = weaker there), adaptation state. All bandit state lives here — the bandit object itself is stateless and rebuilt each plan.
- `adapt/` — decision core (engine, bandit, OU process). Pure in-memory; zero file I/O.
- `scenario/` — `SceFile`, a verbatim line-based `.sce` editor with surgical accessors, + the variant generator.
- `telemetry/` — Raw Input recorder (ctypes message-only window on a daemon thread; packets arrive without focus via `RIDEV_INPUTSINK`) → `MouseTrace` (.npz). One continuous recording per watch session; runs are sliced out via `snapshot().window()`. **`stop()` and `start()` both HONOUR `_teardown()`'s bool** — `stop()` used to discard it, so a pump that outlived the join was reported as a clean stop while its window and process-wide class stayed alive and `_stop_capture` dropped the last reference to it. `_run()` must also check the HWND before `_ready.set()`: a NULL window makes `RIDEV_INPUTSINK` registration fail (no packets at all) while `start()` reports success, and `_teardown` then cannot post `WM_CLOSE`, leaking a thread that pins the whole retention buffer.
- `analysis/` — flick/bias/deficit/notable-moment computation and `RunReport`. Pure leaf over stats + telemetry; never imports adapt/scenario/gui.
- `capture/` — dxcam desktop ring buffer → mp4 clips (`[clips]` extra).
- `optimize/` — the free Process Lasso replacement: `hardware.py` (read-only probes: registry CPU name, ctypes RAM/refresh-rate, one PowerShell CIM call for GPU — wmic is gone on recent Win11 — and live HAGS state via D3DKMT/WDDM-2.7 caps), `checkup.py` (probe/fix pairs; `safe=True` marks per-user reversible fixes eligible for fix-all; probes incl. Game DVR, Game Mode, timer resolution via NtQueryTimerResolution, core parking via `powercfg /qh` — `/q` omits hidden settings; the power fix records its activated scheme GUID under HKCU\Software\kovadapt for locale-independent recognition), `watchdog.py` (daemon-thread poller, tunes once per game PID and records `tune_times`; SMT-aware `cpus_to_free()` — [0,1] only when logical > physical cores; HKCU Run-key startup registration), `recommend.py` (pure advice rendering, gated on `HardwareInfo` properties). Every module imports on any OS; probes return unknowns off-Windows.
- `gui/` — PySide6 single-page app (Dashboard, Scenarios, Analysis, What changed, Adaptability, Optimizer, How it learns) + top-level windows. **`ascii_art.py`** owns ONE stencil per resolution: it used to take a `subtract_glints` flag that produced two materially different irises from the same call (highlights carved out of the fiber detail for static renders, an intact iris plus overlay cells for the splash), so the eye did not look like itself in two of the places it appeared. There is no `glint` role — the specular/halo/catchlight/sheen layer is deleted, not merely unused. The opening's finale is `reticle_flicker()`, a HARD-STEPPED table (no interpolation, every reticle cell on one level, steps ≥ 70 ms because the splash paints at 33 ms and shorter steps get sampled at an arbitrary phase and sometimes never drawn); it sits after `logo._WARP`'s last knot so it runs at 1:1 wall time. **`color.py`** is pure OKLCH math (no Qt): OKLab↔linear sRGB with chroma-reducing gamut mapping, WCAG contrast, and a `fit_contrast` that bisects to the contrast BOUNDARY so an accent gives away no more vividness than the floor demands. `theme.py` DERIVES all four palettes from a base (L, C, H) + an accent preset — colors are computed, never hand-picked, and `tests/test_theme_contrast.py` walks every role pair; `border` is a hairline rule while **`border_control`** carries the real ≥3:1 floor for anything a user clicks (they were one token, so every input on cream sat at 1.29:1). `theme.mono()` snaps to `CELL_SIZES = (12, 14, 20, 24)` — the only sizes where Cascadia Mono's advance AND row pitch are both integers; off-grid sizes fringe under ClearType. Views read `theme.current()` at use time and implement `restyle(pal)` — never cache a palette. `shell.py` gives each section the column width its CONTENT needs (`COLUMN_WIDTHS`: prose 720 / forms 950 / charts+tables 1400). `dashboard.py` is HERO + ONE TREND + PLAY: the `Hero` frozen dataclass makes the because-clause a REQUIRED field, so no code path can render a bare number. `viz.py` charts are character art and the heatmap is zero-anchored + diverging with unmeasured regions as NaN (min-max normalization turned noise into a screaming "weakest zone"). `overlay.py`: frameless click-through session card (Qt `WindowTransparentForInput`, no hooks; `(-1,-1)` is the only unset-position sentinel — coordinates are legitimately negative on multi-monitor). `onboarding.py`: WelcomeDialog + HintBar weakset registry. Dashboard owns the overlay + launcher actions; the Optimizer tab launches `optimizer_window.OptimizerWindow` (owns the `GameWatchdog`; user-close hides it, app-exit `shutdown()` really closes). `replay.TrajectoryReplay` is the ONLY surviving pyqtgraph canvas: two NaN-separated curves, decimation above 50k points, a bounded comet trail. **Never give a panel a layout's vertical stretch** — every panel has a natural height, and handing it the slack made a hint bar fill a section and a sparkline render 1400px tall; put the slack in a trailing `addStretch(1)`.

### On-disk state (`~/.kovadapt/`)

`settings.json` • `profiles/<slug>.json` • `traces/<slug>/<ts>.npz` • `reports/<slug>/<ts>.json` + sibling `clips/*.mp4`. Slug = scenario name with runs of chars outside `[A-Za-z0-9._-]` replaced by `_`; timestamps are ISO with `:` → `-`. `watcher._report_path` derives the reports path by path surgery on the traces path — the two trees mirror each other, and changing `TraceStore`'s directory depth silently breaks report/clip placement.

## Cross-module contracts (breaking these fails silently)

- **Region keys** `r{row}c{col}` (row-major, dims from `Settings.region_cols/rows`) must be byte-identical across `adapt/bandit.py:region_keys()`, `scenario/generator.py:_region_of()`, and `analysis/movement.py:region_deficits()`. A mismatch makes spawn resampling no-op and telemetry credit vanish — no errors raised.
- **`plan()` mutates the profile** (`ou_state`, `movement`, `target_scale`, `last_focus`). Callers must save the profile afterward or persisted state desyncs from the generated `.sce`; never call `plan()` speculatively. `plan(profile, None)` must stay valid (bootstrap path).
- **Ordering in `observe()`**: `credit_focus_region()` before `observe_run()` — folding the run into the EWMA first would contaminate the bandit's own baseline.
- **`ADAPTIVE_SUFFIX` is `" [Adaptive]"` — leading space included.** Profiles are keyed on base+suffix; both base and adaptive runs feed the same profile; the GUI picker hides adaptive variants but loads profiles by the suffixed name.
- **Byte-identical `.sce` round-trip** is test-pinned: writing an untouched `SceFile` must equal the input. `.sce` files contain *duplicate* section headers (`[Character Profile]` per bot) disambiguated by their `Name=` line — hence the (section, name, key) accessor API. Only bots listed in the `AddedBots` header get size/speed edits; spawn resampling only reuses existing coordinates, never invents them.
- **JSON dataclass round-trips** (`PlayerProfile`, `RunReport`) load via `cls(**dict)`: new fields need defaults; removing/renaming a field breaks every existing file under `~/.kovadapt`. There is no schema version key. Trace `.npz` files are versionless too — `MouseTrace.load` must keep tolerating missing keys (`clicks_up` is absent in pre-v0.3 traces).
- **Archetype overrides** (`Settings.archetype_overrides`) are plain dicts of Settings field names; `for_archetype()` silently drops unknown keys so stale settings.json files can't crash `dataclasses.replace`. Engine code must read tunables via `self._effective(profile)`, never `self.s` directly, or archetype behavior silently vanishes.
- **Fatigue never touches persisted state**: `plan(fatigue=...)` eases only the emitted `AdaptationPlan`; `profile.target_scale`/`movement` stay un-eased so the next session resumes true difficulty. The tracker itself is session-scoped — recreated in `watch()`, not persisted.
- **Y axis**: raw mouse `+y` is down. `analysis/` flips to aim-convention (+y up) internally, and `MouseTrace.path()` negates y for plotting — don't "correct" the flip in consumers. `bias_score > 0` means the **left** side is weaker.
- **Time base** is epoch `time.time()` everywhere (trace packets, click times, clip frames, run windows). Cross-correlation of traces/clips/runs works only because everything shares that clock. `MouseTrace.t` must stay monotonic.
- **Determinism**: `plan.seed` is the only randomness reaching the generator, so a given `AdaptationPlan` always regenerates the identical `.sce`.
- **Authored speed is modulated, never replaced**: characters with base `MaxSpeed > 0` get `base * plan.target_speed_mult` (0.65–1.35); the absolute 0–170 ramp (`plan.target_max_speed`) applies only to base-speed-0 static walls. Writing the ramp onto a 1300-speed strafe bot collapses the scenario's difficulty.
- **One gate for every microstructure claim.** Overshoot rates, correction counts, directional bias and per-flick moments are unreadable when input timing is noisy, and `analysis/report.py:input_degraded()` is the ONLY definition of that gate — it lives in `report.py` because `insights.py` and `sens.py` both import it, making that the one module all of them plus the GUI can share. It existed as three inline copies, and the page then said, on one degraded run: header "40% of flicks overshot — consider a slight sens decrease", KPI tile "noisy-input", bias chart "your left flicks cost 3.2× more", and Coach "diagnoses suppressed". Any NEW surface that renders microstructure must call it; `tests/test_analysis_layout.py` regex-asserts no module rebinds the thresholds and that no surface gives a verdict on a degraded run.
- **Never present a number without its evidence.** `gui/dashboard.py:Hero` enforces this structurally (the because-clause is a required constructor field, and `unknown()` still demands one). Cold starts show a dash and say what is missing — never a fake zero, and never a comparison of a run against itself (every EWMA is SEEDED to the first run's own value, so a baseline only exists from run 2). **Count the measurement, not the runs**: `readiness()`'s bias term keys on `bias_obs`, because bias is measurable far less often than a run happens (8+ flicks, 3+ per side; `kovadapt replay` supplies none at all). It once read `1.0 if (run_count >= BIAS_RUNS and ewma_bias) else min(run_count/BIAS_RUNS, 1)` — identically `min(run_count/BIAS_RUNS, 1)`, since the else branch is already 1.0 at that point — and so reported "bias evidence collected" on profiles with zero measurements.
- **`settle_focus(profile, plan)` must be called between every `generate_adaptive_variant()` and the `profile.save()` that follows it.** `plan()` stamps `profile.last_focus` unconditionally, but the generator only learns whether the focus survived after trying to resample spawns — `resample_spawns()` returns nothing when a layout has fewer target spawns than `region_cols*region_rows` (19 of 31 real `.sce` files do). Persisting an unexpressed focus makes `credit_focus_region` book the next run's deficit against an emphasis the player never saw, and that reaches `spawn_weights`, not just the display. The guard lived inline in `process_run` and nowhere else while four other sites did the same plan/generate/save.
- **Rows are not indices, and neither are they clip keys.** `analysis_view` prepends a non-selectable caption row on degraded runs, so `row == moment + 1`. `Qt.UserRole` via `_moment_index()` is the only mapping to trust — for selection, for `clip_files` lookup (keyed by MOMENT in `watcher.py`), and for `restyle`'s per-kind colours. `_update_clip_state` takes a `moment_idx` for exactly this reason: it was called `row`, one correct caller passed an index into it, and on clean runs the two are equal — which is why every test passed.
- **One definition of what counts as a visible zero.** `gui/viz.prints_zero()` is public for that reason: the bars, the footer sentence, the worst-bar highlight and the page headline in `analysis_view` all have to agree about it, and they did not. The chart said "every bar is 0.00 — no cost recorded to compare" while the title above it read "your left flicks cost 1.3x more than your right — 0.00 vs 0.00", a finding carrying its own refutation. Any surface that decides something is "nothing" must call it rather than re-deriving `f"{v:.2f}" == "0.00"`.
- **A caption may not name ink that is not on screen.** The bias caption was a constant ending "the red bar is this run's worst" — a sentence about a colour — and four states put no red on that panel at all (degraded input, no flicks, every bar rounding to zero, and no run loaded yet). Captions that describe emphasis are derived from the same numbers the chart draws (`_bias_caption`), never stored as prose.
- **Semantic colour never comes from `pal.accent`.** The accent is a user preference: under `rose` it is red, under `mint` green. Anything painted with it reports taste as a verdict — the Optimizer's `info` rows (the largest bucket, 5 of 12 live rows) read as errors under rose and all-clear under mint. Status and severity ramps come from `good/warn/bad` plus a neutral, and an ordinal ramp must follow the same order as the sort beside it: the Coach's dots ran backwards against `_SEVERITY_RANK` for two versions, so the most severe card wore amber and the less severe wore red.
- **`reason` is a finding; `error` is a failure.** `SpawnMap` had one field for both, so a base `.sce` that was never opened reported as "the author's own, left untouched" — a positive claim about a file we could not read. Any field whose truthiness drives a *positive* statement must not double as the I/O-error channel.
- **Tests never touch real machine state**: anything that can reach `Path.home()`, the real HKCU registry, or the game folder must be monkeypatched/isolated — the suite once corrupted the developer's real `settings.json` and `HKCU\Software\kovadapt`. GUI smoke tests carry an autouse home-isolation fixture; keep it. Constructing `OptimizerWindow` starts a scan that shells out to PowerShell and reads live power state — stub `rescan` in tests, and tear the window down with `shutdown()`, since `close()` only hides it.

## Optional dependencies & import guards

The core install needs only numpy; everything else is optional and **lazily imported** — keep it that way:

- `cli.cmd_gui` imports the Qt app inside the function and converts `ImportError` into an install hint; `gui/__init__.py` stays import-free so `import kovadapt` never pulls Qt.
- `telemetry/raw_input.py` defines all ctypes/Win32 code behind `RAW_INPUT_AVAILABLE` (`sys.platform == "win32"`); `capture/clips.py` sets `CLIPS_AVAILABLE` via try/except **`Exception`** (dxcam raises non-ImportError errors on unsupported platforms). Both modules must import cleanly on any OS — that is what lets analysis and tests run cross-platform. `watcher._start_capture` imports both lazily.
- In `raw_input.py`, the `WNDPROC` ctypes callback lives on the pump thread's stack frame, and `_run()`'s finally block destroys the window and unregisters the class on the same thread so the registration can never outlive the thunk (a stale class dispatching into a freed thunk is a native crash — that bug shipped once). All Win32 functions have explicit argtypes/restypes on private `WinDLL` handles — the default `c_int` prototypes truncate pointer-sized values and fail by ASLR lottery. Keep the WndProc critical section tiny (runs per packet, up to ~8 kHz).

## Qt gotchas that have each cost real time here

Every one of these was found by LOOKING at a render, never by a failing test.

- **Qt Style Sheets do not implement `text-transform`.** The rule parses and silently does nothing. Uppercase at the call site instead.
- **QSS cannot draw a CSS triangle.** The browser idiom — zero width/height, transparent left/right borders, one solid border — parses and renders a SOLID RECTANGLE. Every combo box and all 25+ Adaptability spin controls shipped a filled block where their caret belonged. Deleting the rule is not a fix either: once a widget is styled Qt draws no arrow at all. `theme._arrow_url()` generates a real supersampled PNG caret (hand-rolled from `zlib`, because `build_qss()` must stay callable with no QGuiApplication — the contrast tests call it that way) and caches it under the system temp dir.
- **An attribute selector and a pseudo-state carry EQUAL CSS2 specificity, so the later declaration wins.** `QPushButton:pressed` is declared before `QPushButton[accent="true"]`, so the accent fill was never replaced on click and the app's primary button was byte-identical up and down in all 20 theme × accent combos. Any `[attr]`-scoped widget needs its own `[attr]:state` rules; the generic ones cannot reach it.
- **A `QMainWindow` background is the BOTTOM of the paint stack.** A translucent gradient stop there has nothing to blend into, so Qt fills the alpha from the cleared backing store — black. A "subtle 7% accent glow" rendered as a charcoal box (luminance 20 against a page of 244 on cream) and survived two versions because on the dark themes the hole sits within a few points of the page. Composite window-level colours yourself (`theme._glow`); child widgets may still use `rgba()`, because they *do* have a parent painted behind them.
- **Reproducing a Qt ALPHA means an sRGB lerp, not `color.mix`.** `color.mix` interpolates in linear light, which is the better model of light but the wrong model of `SourceOver`: it favours the brighter colour, and the same 10% ratio came out four times too strong (luminance 76 on a page of 23).
- **A `QVBoxLayout` gives a non-stretched child its `sizeHint`, and `QTableWidget.sizeHint()` is Qt's content-independent `QSize(256, 192)`.** So `setMaximumHeight()` above 192 does nothing: a "fit to content" that sets only a maximum works downward and never upward. 80 scenarios rendered as a five-row porthole with 531 px of empty page below.
- **The `offscreen` QPA platform has no font database on this machine** — every glyph renders as a missing-character box. Any render you intend to LOOK at must use the default platform with `widget.grab()`, which needs no visible window. `tests/test_window_glow.py` is the working pattern. (Tests that only assert text/geometry are unaffected, which is why much of the suite sets it.)
- **A bare `&` in any widget text is a keyboard mnemonic**, so `QGroupBox("Telemetry & clips")` renders as "Telemetry _clips". Write `&&`.
- **The app-wide QSS `*` selector outranks `QWidget.setFont()`.** A numeral styled only with `setFont` renders at the sheet's body size in the running app while looking correct in tests, where no app QSS is installed — restate family and size in a widget-level sheet (`_mono_css`).
- **`QGroupBox::title` with `subcontrol-origin: margin` is positioned inside the box's `margin-top`** — that margin IS the clearance between label and border. Too small and the title sits on the line.
- **Size a `drawText` rect to the font's line box, not to a round number.** An 8 pt face needs ~15 px; a 12 px rect clips its own descenders, and a fixed-size widget derived from the smaller number then clips the caption again. Derive the widget height from the same terms that place the caption.
- **Never give a panel a layout's vertical stretch** (also in the `gui/` notes above) — put slack in a trailing `addStretch(1)`.
- **A `QThread` destroyed while running is a fatal abort.** `MainWindow.closeEvent` waits on the watcher worker AND the boot worker; anything else parented to a window needs the same.
- **A QSS type selector matches SUBCLASSES.** `QMainWindow, QDialog, QWidget { background: bg }` therefore reaches every checkbox, frame and scroll viewport in the app, and each one painted the page colour *opaquely on top of* its group box's translucent plate — a 350×18 page-coloured stripe across a panel, a full rectangle behind the checkup list. `QLabel` had been exempted by hand for exactly this, and `shell.py` works around it with `objectName("tabPage")`; the fix is to keep extending that exemption list. `.QWidget` (dot-prefixed) matches the exact class only, but does not help for viewports, which *are* plain `QWidget`s.
- **An instance stylesheet cascades to children.** `widget.setStyleSheet("background: transparent")` transparents the widget *and everything inside it* — set on the Optimizer's check rows it took the Fix button's accent fill to `#010102`. Scope it to the class: `setStyleSheet("_CheckRow { background: transparent; }")`. PySide publishes the Python class name to QSS, so a Python-side subclass name works as a type selector.
- **No global selector can name `QComboBoxPrivateContainer`**, the widget holding a combo popup's list. Fusion paints its own `PE_PanelMenu` under it — on cream, a *square* `#969288` outline around a 6 px-rounded list plus a 5 px band top and bottom. An INSTANCE stylesheet on the container does reach it and is the whole fix. A `QProxyStyle` is not: once a stylesheet is set, Qt inserts `QStyleSheetStyle` *above* any proxy and answers `PM_MenuVMargin` itself without delegating down — a spy on the proxy records the metric never being asked for.
- **`QStyle::polish` is three overloads** — `QWidget*`, `QApplication*` and `QPalette&` — and one Python `def` catches all of them. Without an `isinstance` guard it reaches for `.metaObject()` on a `QPalette` and takes the process down with no traceback.
- **An app-wide event filter sees every event for every object.** Installing a second copy doubles that cost; installing one per test case stacked twenty and put four minutes on the suite, all of it in the tests that ran afterwards. Remove the previous filter before installing a new one.
- **`MainWindow` construction blocks the event loop ~0.6 s**, so the splash shows its dark stage first and starts its choreography clock *afterwards* (`SplashScreen.begin()`); starting it before meant the whole first beat was never painted.

## Tests

The suite (983 tests, ~4 min — GUI smoke and offscreen renders dominate the runtime) pins behavior, not just shapes: byte-identical `.sce` round-trip over every installed real file (incl. BOM and CRLF preservation), the stats filename grammar (scenario names may contain `" - "`; the scenario regex group must stay greedy), the accuracy deadband, the +y-up flick-angle convention, watcher end-to-end against a fake stats tree, CLI output contracts, launcher URL/playlist schemas, and offscreen GUI smoke. Newer pins worth knowing: WCAG contrast across every theme × accent × role pair (`test_theme_contrast.py`), that no Analysis surface gives a microstructure verdict on a noisy run, that a zero-shot run never reaches the EWMA or the bandit, that invincible-target tracking scenarios are not stamped "clicking", and that the watchdog resolves the renderer rather than Steam's launcher stub. `tests/test_telemetry.py:TraceBuilder` synthesizes ground-truth mouse traces — use it for new analysis tests. The Thompson bandit intentionally keeps ~15–25 % exploration; convergence tests assert a plurality (≥ 25 of last 50 picks), never a monopoly — don't tighten these assertions or "improve" exploitation.

`tests/test_window_glow.py` holds the RENDERED pins for app chrome (window glow, combo caret taper, primary-button pressed state); `test_theme_contrast.py` holds the pure-math ones and now covers `selection` — which is fitted against `bg_alt`, the surface selections are actually painted on, at `SELECTION_CONTRAST = 2.6` rather than the 3.0 control floor because at 3.0 the text on top drops to 4.08:1.

**A green suite is not proof a screen looks right**: render it and LOOK — the hero numerals rendered at body size while every test passed, because the assertions were all about text content. **And verify by mutation — then check the mutation actually applied.** A regex "removing" a QSS rule silently matched nothing (`[^}]*` stops at the `}` inside `{p.accent_press}`), so a test appeared to be mutation-proof when it had never been challenged; assert the literal is present before replacing it.

Three more ways a rendered test can be unable to fail, each of which has happened here:

- **A byte-length-preserving mutation leaves stale bytecode behind.** `5`→`3`, `hide`→`show`, `72`→`110` all keep the file's size, so Python's `(mtime, size)` staleness check is satisfied and the *mutated* `.pyc` is reused after the source is restored — reporting failures for code that is no longer there. Clear `__pycache__` between mutation runs, or run with `py -B`.
- **A test that does not pin the STYLE is testing a different app.** The combo-popup test passed with the fix removed because its fixture never called `setStyle("Fusion")` — and the defect under test is Fusion's own chrome. Same root cause, different symptom: the app-wide stylesheet lives on the `QApplication` the whole session shares, so it carries whatever the previously-run module left there, and pixel measurements silently depend on module order. Apply a known palette in the fixture and put the previous sheet back on teardown.
- **`deleteLater()` does nothing without a loop turn.** Widgets built per parametrized case accumulate in that shared application, and every later `theme._apply` re-polishes the whole heap — 0.25 s per case became 3.5 s. `setParent(None)`, `deleteLater()`, then `processEvents()`.
